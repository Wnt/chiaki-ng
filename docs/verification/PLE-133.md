# PLE-133 — narrow `stream_performance_mode` to power management

## Decision

Keep the persisted `stream_performance_mode` preference and its default-off switch, but narrow it to
the two power-management requests it was originally meant to group:

- Android sustained-performance mode, when `PowerManager` reports support; and
- ADPF frame-budget hints, when `PerformanceHintManager` successfully creates a session.

The flag no longer changes the MediaCodec format. In particular, it no longer adds
`frame-rate = stream fps`, `operating-rate = fps × 4`, or a decoder-only configure fallback tier.
Decoder operating rate is owned exclusively by the independent explicit, default-path, real-PTS auto,
and low-latency controls.

The preference key is intentionally unchanged. Existing installs that stored
`stream_performance_mode=true` continue to request the supported power-management legs, without a
migration and without silently losing the user's opt-in. The UI now calls the setting **Stream
power-management hints** and describes only those requests.

## Evidence

- [PLE-79](PLE-79.md) measured the old flag on SM-S908B / Exynos 2200. Sustained-performance mode
  was unsupported and ADPF session creation was rejected, leaving only `operating-rate=240`. That
  rate did not improve latency and had small CPU regressions in the untouched runs.
- [PLE-116](PLE-116.md) swept operating rates independently. `960` reduced untouched decode from
  7.55–8.02 ms mean / 9.57–9.73 ms p95 to 6.80–6.86 / 8.56–8.64; `1920` added nothing. Its explicit
  conclusion for this ticket was that the old `fps × 4 = 240` leg is dominated.
- [PLE-172](PLE-172.md) confirmed `960` on the default timestamp path and promoted
  `stream_decoder_operating_rate_default` to default-on. Therefore removing the old decoder leg does
  not remove the shipped decoder-rate optimization: the stronger, independently switchable setting
  now owns it.
- PLE-132 already made both remaining power legs report actual platform acceptance. Diagnostics can
  therefore name only live `perf-sustained` and `perf-adpf` legs; the old `perf-oprate` marker is
  removed.

## Resulting behavior

| Setting state | Decoder behavior | Power-management behavior |
|---|---|---|
| `stream_performance_mode=false` | Independent operating-rate controls only | No sustained-performance or ADPF request |
| `stream_performance_mode=true` | Same independent operating-rate controls | Request supported sustained-performance and ADPF legs |

The setting remains off by default. The runtime change is isolated by that existing opt-in: users
with it off are unchanged, while users with it on stop receiving its redundant decoder request.

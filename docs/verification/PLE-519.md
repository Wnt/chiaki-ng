## Result

`grep -c "requestLayout() improperly called by" ple519_s22_handheld_logcat.txt` → **6** lines
total in the whole capture, **0** naming `streamControlDock` or `overlay`
(`grep "requestLayout..." | grep -oE "streamControlDock|overlay"` → no matches). The 6 lines
that remain are unrelated to PLE-513's finding:

* 2x `app:id/consoleListContainer` (`MainActivity`'s host list `FrameLayout`), both before
  `StreamActivity` even starts (10:16:34–36, host-list screen during launch).
* 3x from `com.android.systemui` (pid 3348, not this app) at 10:16:36, System UI's own
  status-bar/QS views reacting to the app's rotation lock — outside this app's process
  entirely.
* 1x `app:id/controlsFragment` (a `ConstraintLayout`, not `streamControlDock`/`overlay`) at
  10:16:43.089, the same second `StreamActivity`'s window is created — a one-off during
  activity startup, not a per-frame loop.

None of the 6 recur (each is a single line), none occur during the 60 s settled steady-state
window (all are clustered in the 6-second launch/connect transition before "Stream window
created"), and none name the `streamControlDock`/`overlay` pair PLE-513 fixed. PLE-513's
acceptance criterion — zero `requestLayout() improperly called` from `streamControlDock` /
`overlay` across a 60 s stream — holds on this fresh capture.
